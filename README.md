Image Analyzer Pro 是一款基于视觉大语言模型 (VLM) 的高性能图片审计与全场景分类工具。它专为大规模图片库设计，通过高度自定义的提示词 (Prompt) 逻辑，将海量图片的“内容理解、自动分类与重命名”一站式自动化。

## 🌟 为什么选择它？

- **工业级分类精度**：默认内置“视觉内容分类员”指令，能精准识别各类照片、截图、办公文档资料等，而非简单的关键词过滤。
- **全场景无限扩展**：**核心逻辑完全由 Prompt 驱动**。您可以随时通过配置文件，将它变身为“猫咪行为分析师”、“截图整理助手”或“发票分类器”。
- **多模型并发矩阵：支持在配置中挂载无限个不同（或相同）的 AI 模型 Endpoint。程序会根据模型列表长度自动开启多线程，突破单一 API 账号的速率限制（RPM/TPM），实现性能倍增。**
- **极致的鲁棒性**：配置热切换（无需重启）、CSV 防占用自动重试、多线程安全锁、环境自愈脚本（自动装 Python，仅适用于Windows）。

## 📂 应用场景示例

1.  **相册智能分拣（核心案例）**：自动化筛选本地图库，精准定位并分拣出生活照、截图、办公资料。
2.  **安全合规审计**：通过精细化的 Prompt，从海量图片中提取不合规或令人不安的内容。
3.  **素材库整理**：自定义“自然风景、工业生产、UI设计”等规则，让 AI 自动将杂乱的素材库按题材整理进对应文件夹。
4.  **数字化标签管理**：为每张图片自动生成精准短标题，并汇总至 CSV 表格，建立可搜索的数字化图片档案。

## 🚀 快速开始

### 1. 准备环境与 API 建议
- 确保系统连接互联网。
- 准备一个支持 Vision 能力的 OpenAI 兼容接口（例如[SiliconFlow 平台](https://cloud.siliconflow.cn/i/My0p5Jgs)） 。
- **性能提示**：建议根据预算和速度需求在 `config.yaml` 中选择不同的模型梯度，如 `THUDM/GLM-4.1V-9B-Thinking`（支持免费使用）、`Qwen/Qwen3-VL-32B-Instruct`（TPM较高）、`GLM-4.6V`、`Qwen3-VL-30B-A3B` 等。但需要注意，由于不同计费模式的模型具有不同的 **TPM (Tokens Per Minute)** 频率限制，如追求处理速度还是建议自己购买适配的 AI 模型服务。

### 2. 配置与运行
1.  **编辑 config.yaml**：填入您的 API 密钥和图片目录。
2.  **自定义分类 (可选)**：在 categories 下修改或添加您想识别的任何内容。
3.  **启动程序**：
    - **Windows 环境**：双击 **run_analyzer.bat**，它会自动检查并部署 Python 环境后启动任务。
    - **Mac / Linux 环境**：本项目核心逻辑完全跨平台。请先执行 pip install -r requirements.txt，然后终端运行 python main.py 即可。

## ⚙️ 配置文件核心项说明 (`config.yaml`)

本项目所有的核心逻辑与参数均由 `config.yaml` 驱动，支持极致的自定义配置：

### [API 核心连接配置]
| 配置项 | 说明 |
| :--- | :--- |
| `api.key` | API 访问密钥（支持各大兼容 OpenAI 格式的平台）。 |
| `api.base_url` | API 请求的基础 URL 地址。 |
| `api.endpoints` | **【核心特性】**多模型配置列表。列表包含 `key`, `base_url`, `model`。配置多少个节点，程序就会启动多少个并发线程进行异步处理。 |
| `api.timeout` | 单次网络请求的超时上限（秒），防大图传输卡死，建议 180s。 |
| `api.max_retries` | 接口请求失败（如网络波动/限流）后的自动重试次数。 |
| `api.temperature` | 采样温度 (0.0-1.0)，建议调低 (如 0.1) 保持分类输出的严谨性。 |
| `api.max_tokens` | 允许模型生成的最大 Token 长度。 |

### [图片预处理配置]
| 配置项 | 说明 |
| :--- | :--- |
| `image.source_dir` | 待处理的原始图片存放目录（支持直接粘贴 Windows 绝对路径）。 |
| `image.max_dimension` | 图片的长边缩放上限，超过此像素值会自动等比缩小，以减小传输压力。 |
| `image.extensions` | 程序扫描的图片文件后缀名白名单（如 `.jpg`, `.png` 等）。 |
| `image.auto_rename` | 开关：是否根据 AI 生成的“短标题”自动进行物理重命名。 |
| `image.keep_original_name` | **重命名策略**：设为 `true` 则生成 `短标题_原文件名.jpg`；设为 `false` 则仅保留 `短标题.jpg`（程序内置了完善的重名防覆盖后缀自增逻辑）。 |

### [分类审计定义与存储规则]
| 配置项 | 说明 |
| :--- | :--- |
| `categories` | **完全自定义的审计规则库**。包含任意个您定义的分类 Key（如 `photo`、`screenshot` 等），该 Key 将作为系统识别标签发给 AI。 |
| `path` | 识别结论为该类时，图片物理移动的目标子目录。 |
| `desc` | **发给 AI 的视觉判定准则**，通过详尽客观的特征描述引导 AI 做出精准分类。 |

### [系统运行行为配置]
| 配置项 | 说明 |
| :--- | :--- |
| `system.concurrency` | 当未配置 `api.endpoints` 列表时生效的并发数。默认值为 1，通常 1-4 较为安全。 |
| `system.csv_file` | 最终识别结果汇总电子表格的存放名称。 |
| `system.log_file` | 运行过程中的详细操作日志文件名。 |
| `system.prompt_template` | **核心大脑**：发送给 AI 的提示词模板，自动提取上方的 `desc` 规则完成动态注入。 |

## 🛠️ 技术保障

- **断点续传**：支持中断后重启，自动跳过已处理的文件。
- **碰撞防护**：重命名时若遇冲突，自动应用自增序号，绝不覆盖文件。
- **隐私保护**：仅发送图片视觉内容，自动剥离本地物理路径。
